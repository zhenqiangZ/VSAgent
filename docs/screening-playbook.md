# 筛选细则（`AGENTS.md` 的展开）

`AGENTS.md` 是确认点与许可，四十来行；这份是它后面那些「怎么做」。
**讲到具体数字或具体参数之前读对应那一节**——不读就写，写出来的多半是编的。

模型读它的方式是 `read`：`AGENTS.md` 里每一个确认点末尾的「细则 §N」就是指向这里的。

---

## §1 结构

### 1.1 意图清楚之后，先把蛋白讲清楚

身份、物种、家族、功能一句话、已知结合位点或催化残基、相关突变与异构体；再说清它
「对什么敏感」——已报道的活性分子分几类、每类的代表分子与活性量级、哪些是共价或
别构、哪些只是早期苗头。

给用户的一段话必须包含：蛋白是谁、位点在哪、已知活性分子分几类、每类代表分子与
活性量级。然后问：你想筛的是哪一类？有没有必须保留或必须避开的骨架？
用户没有给出方向之前，不要往下走。

### 1.2 取证顺序：先查本地，再查文献与网页

讲到**具体数字**（活性量级、IC50/Ki、临床阶段、突变影响、选择性倍数），或者要**介绍一个
蛋白**时，都不能只凭记忆。按下面这个顺序取证，**命中就停**，不要每条都走到底：

1. **`search_corpus`（免费、离线）**：本地语料库里有用户导入的文献与之前搜过的网页。
   中文提问也能命中英文文献，不必先翻成英文。命中相关片段就用它的引用号
   （`doc#…` / `web#…`），要读上下文用 `read_source`。
2. **本地没有、或命中的都不相关**：要**已发表文献**用 `search_literature`（PubMed，免费）；
   要**最新进展、厂商资料、指南**用 `search_web`（计费，约 0.005 元/次，本会话前 10 次不问）。
   联网搜到的网页**当场进本地语料库**，同一句 query 再搜不花钱；写完这一步再用
   `search_corpus` 检索一遍，拿引用号引用刚查到的内容——介绍里每个数字都要能指到一条来源。
3. **都查不到**：如实说「本地语料与 PubMed 都没有查到」——**不要**把查不到写成
   「没有这回事」。

三个工具分在 `corpus` / `websearch` / `literature` 族，第一次用之前 `load_tools` 装上，
**一次把这一段要用的族装完**（装一次改一次工具清单，下一步的缓存会失效）。

**不要变成检索远征**：只查要写进结论的那几个数；一次取证最多两轮
（本地一次 → 不够再联网或 PubMed 一次），查不到就如实说，不要换着关键词反复搜。

### 1.3 结构全景：先铺开分母，再谈候选

用户没有点名结构时，先调 `survey_structures(accession=…)`：它把这个靶点在 RCSB 登记的
全部实验结构取回来，按共晶配体分组，每组给套数、最佳分辨率与代表条目；聊天里是摘要，
全表在 `#/survey/<id>` 页面里（地址用 `open_viewer` 取）。这一步给的是**分母**——
「这个靶点被研究到什么程度、有哪些配体结合过」——不是候选清单，也不是结论。

先验知识仍然要说：这个蛋白可能的口袋、每个口袋的代表配体、你认为对应的 PDB 编号。
说的时候必须原样带上这句：「以下是待验证的假设，未经核对，不作为依据。」。候选要落在
全景里的条目上；全景里没有的编号单独标出来，说明它是记忆里的、待核对。

只按 UniProt 铺开有一个已知的盲区：它只返回**已沉积**的结构。文献里有、但没有解出结构的
口袋（别构位点、未成药的浅槽）不会出现在里面。所以全景之后仍按 §1.2 查一遍文献，
把「有结构」与「只有文献」两类位点分开写。

两道核对，按顺序做，缺一不可：

1. **编号是不是真的存在。** 逐个确认它确实是已发布的条目。不存在的剔除，
   并在报告里列出来，不要静默丢掉。
2. **序列是不是受体序列。** 把取回来的坐标里各条链的序列与该蛋白的序列比对，
   对不上的条目剔除，同样在报告里列出来。

两道都通过的条目才进入下一步。核对结果要逐条报给用户：通过了哪些、剔除了哪些、
每一条为什么。

## §2 口袋

### 2.1 叠合与算口袋

· 以**受体自己**为参考系，把各份复合物的坐标都叠合到它上面，逐份报出 rmsd。
  拿受体当参考系、而不是拿第一份复合物：口袋的中心最后要当盒子用，而盒子是在
  受体的坐标系里——拿复合物当参考系，算出来的中心对不上受体。
· rmsd 明显超过阈值的说明不是同一个位点、或不是同一构象，要单独说明，不要混进去。
· 把叠合后的全部配体坐标聚成簇，逐簇圈出 5 埃以内的受体残基，算出中心。
· 每个口袋要说清：编号、中心、来自哪几个复合物与哪个配体、圈住了哪些残基、
  叠合 rmsd。**不要自己编 score**——实验定位没有打分这回事。

**每处口袋都要给一份画像**，工具已经把它算在口袋对象里（`profile`）：

| 项 | 内容 | 怎么来的 |
| --- | --- | --- |
| 配体 | 代号、重原子数、元素组成、伸展尺寸 | 数配体原子 |
| 壁 | 芳香 / 疏水 / 极性 / 带电各几个残基、最近的那个残基与距离、3.5 埃内的几个 | 按残基名分类，距离现算 |
| 判断 | 一句「窄长、以疏水壁为主、四周围得紧」这样的话 | 由上面两组数得出 |

转述给用户时把画像一起说，**不要只报中心与残基数**。画像里没有分数，也不要给它配一个。

**脂质、磷脂、去垢剂不算配体**，算口袋之前就剔掉，排除个数与原因要跟着结论一起说
（`detect_pockets` 的输出里是「筛掉的杂原子组」那一行；运行目录里是
`provenance.pockets.excluded`）。判据是四条全中：碳数 ≥ 8、极性原子（N/O/S）≤ 2 或含磷、
重原子 ≥ 16、包围盒最长边 ≥ 16 埃；另有一份去垢剂代号名单。只看元素会把类固醇药物一起
筛掉，所以最后那条「伸展长度」不能少。

叠合、核对、算口袋这三步由**写运行目录那一个动作一并完成**：把编号清单交给它，
它逐个核对、叠合、算口袋，并把逐条结论一起返回。不要自己分头去做——分开做的话，
报出来的 rmsd 与页面上的口袋对不上。

### 2.2 展示

写成一份运行目录（`write_run(view=pockets)`），再用 `open_viewer(pocket=…)` 取结构页
地址，让用户在看板上看口袋位置。地址要直接打开选定口袋的局部视图；消息里同时给口袋
编号、画像与地址，不要用残基表代替页面。

### 2.3 没有明确口袋时

按先验清单取证后仍然没有口袋时，转预测这一侧；这一步工具会自己做，不需要你决定。
两条路都拿不到就如实说明是「查了确实没有」还是「没查成」，这两者对用户的含义相反。

### 2.4 用户给的口袋

口袋一律以用户的选择为准，不是以你呈现的排序为准。用户给出的与呈现的不同时，
问清依据，并接受四种形式：

· 一个 PDB 编号（重新取该结构核对）
· 用户自己提供的结构文件（结构走 `import_structure`，配体走 `import_ligandset`，
  文献走 `import_documents`）
· 显式的盒子中心与边长（准备受体时手动给）
· 残基编号（`define_pocket` 的 `residues`，形如 `A:315,A:319`；盒子按残基包围盒算）

用户报残基编号时直接用第四种，不要请用户改写成前三种。

## §3 对接前的最后确认

· 用 `prepare_receptor` 先做一次预演（默认那次不写盘），把「会删掉哪些水与杂原子、
  盒子算在哪、哪些残基匹配不上」摆给用户看。
· 预演结果念给用户听，等用户说可以，再用 `confirm=true` 真正写盘。
· 参数是用户的选择：留哪条链、共晶配体用哪个、盒子要不要手动给、padding 多少，
  有分歧先问，不要自己定。
· 用户要换受体时用 `switch_receptor`，并说明换掉之后哪些已有产物不再适用。

## §4 对接

### 4.1 配体从哪来

· 用户自己给的库：`import_ligandset` 收 `.sdf` / `.sd` / `.smi` / `.csv`，然后
  `prepare_ligands`。先用 `confirm=false` 预演，把去重后的条数、性质范围、会截断到多少
  报给用户；用户说可以再 `confirm=true`。**不要不问就准备一整库。**
· ChEMBL 的活性/类似物结果：`search_actives` / `find_analogs` 产出的 ligandset 可以直接
  交给 `prepare_ligands`，同样先预演再确认。

### 4.2 先报参数，再问

调 `dock` 之前，把这几样摆给用户：

· 受体 handle 与口袋来源；
· 盒子中心与边长（从已准备受体的 `box.txt` 读出来，**不要自己算、不要自己改**）；
· 配体总数、本次 `limit` 取多少、还剩多少没处理；
· `exhaustiveness` / `num_modes` / `seed` / `cpu` / 单配体 `timeout`。

参数是用户的选择。用默认值也要说一句「按默认参数跑」，不要静默替用户定。
要换盒子就回 `prepare_receptor` 重跑；`dock` 的签名里没有盒子参数，这是刻意的。

单批可能跑很久：`limit` 个配体 × 单条 `timeout` 是最坏情况，先把这个量级说清楚。

### 4.3 结果怎么读

· 分数**越低越好**（kcal/mol）。只能在同一受体、同一盒子、同一套参数内比较，
  **不是结合自由能，不能跨靶点比较**。
· 必须报：可评分几个、转出 PDB 几个、失败几个、未处理几个；最佳分数与配体效率；
  失败原因（超时 / Vina 非零退出 / 没有结果 / 位姿转不出 PDB）。
· 区分「没筛出东西」与「没筛成」：前者是结果，后者是故障，对用户的含义相反。
· **不要自己编分数、不要手算排名、不要挑一个「看起来合理」的构象当结论。**
  所有数字来自 `dock` 的返回或 manifest。

### 4.4 上网页

对接结果要进运行目录，走：

```
write_run(receptor=..., docking=artifact#N, affinity=artifact#K, interactions="top")
open_viewer(run=artifact#M)
```

`write_run` 会把最佳 pose 复制进 `ligands/`、填 `molecules` 的分数与排名、
写 `provenance.poses`；给了 `affinity` 还会写 `molecules[].affinity_pk` 与
`provenance.affinity`；给了 `interactions` 会给每个写入的位姿算接触与几何氢键，
并对前 8 个算 PLIP 指纹。**不要手动复制 pose 文件，也不要自己拼 meta.json。**
`write_run` 的 `docking` 与 `ligands` 二选一：前者已经带着配体集。

### 4.5 不要做的事

· 不要在受体或配体集还没 prepared 时调 `dock`；原始结构/原始配体集会被拒绝。
· 不要用对接分数替代实验活性，也不要把一次对接的排名当成「筛选结论」。
· 不要在一次结果里跨受体、跨盒子、跨参数比较分数。
· 不要为了「多跑几个」擅自把 `limit`、`exhaustiveness`、`timeout` 调到用户没同意的值。

### 4.6 亲和力打分（DTA）

顺序：

1. 受体准备时保留与选定口袋对应的共晶配体；微调的口袋从这里截出。
2. `search_actives` 取带 pChEMBL 的配体集。少于 40 个化合物不做微调，只走对接单路。
3. `fit_affinity(confirm=false)` 预演，报样本量、pK 范围、训练/验证切分与 5–10 分钟耗时。
4. 用户确认后 `confirm=true` 训练，产出 `kind=model` 的 artifact。
5. 对接完成后，`score_affinity(model=artifact#M, ligands=dock 产物)`，默认前 50 条。
6. `write_run(docking=…, affinity=…)` 把两路分数写进同一份运行目录。

读法：

· pK 越高越好，dock 的 kcal/mol 越低越好；两种分数不能直接比大小。
· 只对训练时的口袋有效；换口袋或换受体要重训，旧模型作废。
· 40–100 个活性时排序力有限：回顾性曲线是 100 个→ρ 0.04、300 个→0.18、726 个→0.39。
· 报样本量与验证指标；RMSE 不代表排序力。
· 两路名次一致与背离的分子都要说，背离的分子往往是最值得看的一批。

### 4.7 相互作用

`write_run(docking=…, interactions="top")` 是默认：所有写入的位姿算几何接触与几何氢键，
前 8 个再加 PLIP；`"all"` 给全部位姿加 PLIP；`"none"` 不算。结构页的分子模式会在
三维里画作用线，侧栏列类型、残基、原子、距离、角度。

PLIP 没算成时，几何接触与几何氢键照画，并写明盐桥、π 堆积、卤键、水桥、金属配位
这几类没有算。不要在消息里贴一张残基距离表让用户自己还原三维；三维页是主件。
