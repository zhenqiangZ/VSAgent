# Screening Playbook

## 0. 使用说明与执行总览

本文件定义 VSAgent 在分子筛选任务中的具体执行流程，包括结构选择、口袋识别、受体准备、对接、打分、项目盘点及结果交付。

本文件与 `AGENTS.md` 配合使用：

- `AGENTS.md` 定义行为边界、确认机制和禁止事项。
- 本文件定义具体操作步骤、工具调用、参数及结果判读。
- `reference.md` 提供科学依据、方法适用条件和案例。

### 0.1 执行原则

1. 先明确研究目标，再选择筛选路径。
2. 先核验证据，再执行计算。
3. 先展示候选方案，再由用户确认。
4. 先预演，再执行正式操作。
5. 每个计算结果均应关联当前任务、受体和口袋。
6. 不得将工具输出直接等同于科学结论。

### 0.2 任务主流程

研究对象确认
→ 证据检索
→ 项目盘点
→ 受体结构选择
→ 口袋定义
→ 受体准备
→ 配体准备
→ 对接与评分
→ 候选分析
→ 实验假设与结果交付

上述流程并非所有任务都必须完整执行。Agent 应根据用户目标和现有证据选择必要步骤，但不得跳过 `AGENTS.md` 规定的确认点。

## 1. 研究对象与结构选择

### 1.1 蛋白介绍与筛选意图

当用户提供靶点、蛋白名称、PDB ID、配体名称或其他研究对象时，首先确认任务意图。

若用户尚未明确筛选目标，应先完成基本信息检索，再询问：

**“你想拿它做什么？”**

检索应优先使用本地 corpus。若本地证据不足，再检索 PubMed 或 Web。

网页检索获得的有效证据应回写语料库，并在回写后再次检索。命中充分证据后停止扩展，原则上最多进行两轮检索。

输出至少包括：

- 研究对象的基本信息；
- 已知配体或活性化学型；
- 已知结构与口袋信息；
- 相关机制或生物学背景；
- 关键证据及来源；
- 当前信息缺口。

不得在研究意图尚未明确时直接启动完整对接流程。

### 1.2 结构选择与核验

结构选择前，应汇总可用的受体结构并进行比较。

建议检查：

- PDB ID 及结构来源；
- 实验方法和结构质量；
- 分辨率或其他质量指标；
- 蛋白链及链完整性；
- 缺失残基或缺失区域；
- 结构中是否存在配体；
- 配体是否具有参考意义；
- 结构是否适用于当前研究问题。

对于多个候选结构，应进行必要的结构叠合和比较。

如果结构间存在显著差异，应说明这些差异可能如何影响口袋定义和后续筛选。

### 1.3 结构叠合与配体分析

结构叠合应使用对应工具完成。

需要时，应计算：

- 结构 RMSD；
- 配体 RMSD；
- 配体相似性；
- 配体聚类结果。

不得手动估算上述指标。

结构比较应结合结构质量、配体信息及研究目的，而不能仅根据 RMSD 选择受体。

### 1.4 结构证据与先验声明

在进入口袋分析前，应明确当前结构选择的依据。

结构证据可包括：

- 已知活性配体；
- 实验结构；
- 文献报道的结合模式；
- 关键残基；
- 结构保守性；
- 其他可核查证据。

应区分：

- 已有实验支持的结构事实；
- 文献提出的机制解释；
- Agent 根据结构提出的假设。

用户确认受体结构后，才进入口袋定义阶段。

## 2. 口袋识别、定义与展示

### 2.1 受体参考系与口袋定义

口袋识别应以当前已确认的受体结构为基础。

对于具有参考配体的结构，应优先利用配体及其周围结构信息定义口袋。

涉及多个受体结构时，应先进行必要的结构叠合，并确认各结构处于可比较的参考系中。

口袋分析应包括：

1. 参考配体定位；
2. 结构叠合；
3. 配体聚类；
4. 配体周围残基识别；
5. 口袋空间范围计算；
6. 口袋结构特征总结。

配体周围残基可采用 5 Å 邻域作为初始分析范围，但应明确该范围是分析参数，而不是所有体系均适用的固定生物学边界。

应记录：

- 口袋定义方式；
- 参考配体；
- 口袋残基；
- 口袋空间范围；
- 口袋的极性、疏水性及形状特征；
- 口袋与已知活性机制之间的关系。

### 2.1.1 口袋画像

口袋画像应综合考虑：

- 残基组成；
- 疏水与极性区域；
- 氢键供体和受体分布；
- 电荷分布；
- 空间形状；
- 口袋可及性；
- 参考配体的结合模式。

对于具有明显结构差异的口袋，应说明其可能对应的不同结合模式。

### 2.1.2 脂质或去垢剂相关结构

当结构中存在脂质、去垢剂或其他非典型配体时，应判断其是否可能反映真实结合口袋。

可采用以下四项判据进行初步筛查：

| 判据 | 条件 |
|---|---|
| 碳原子数量 | C ≥ 8 |
| 极性原子数量 | 极性原子 ≤ 2，或分子含磷 |
| 重原子数量 | ≥ 16 |
| 包围盒尺寸 | 最长边 ≥ 16 Å |

上述条件用于识别可能具有口袋参考意义的结构组分，不应单独作为确定真实结合位点的充分证据。

需要结合：

- 结构环境；
- 配体位置；
- 周围残基；
- 文献证据；
- 结构重复性；

判断其是否适合用于口袋定义。

相关叠合、计算和口袋核验应尽量通过统一工具流程完成，避免不同步骤使用不一致的参考系或口袋定义。

### 2.2 口袋展示

口袋展示应使用户能够核查：

- 当前受体；
- 口袋位置；
- 参考配体；
- 口袋残基；
- 口袋边界；
- 关键相互作用区域。

对于具体结构、口袋或位姿，应提供可打开的结构页面或可视化产物。

展示结果应明确区分：

- 结构中实际存在的配体；
- 计算得到的口袋；
- Agent 推测的潜在结合区域。

### 2.3 无明确口袋时的处理

当没有可靠参考配体或已知口袋时，不应直接指定唯一口袋。

应先：

1. 检查已有结构证据；
2. 汇总可能的口袋区域；
3. 比较不同口袋的结构特征；
4. 说明各候选口袋的依据和不确定性；
5. 将候选口袋提交用户选择。

若当前证据不足以支持口袋定义，应明确说明限制，并提出可验证的后续方案。

### 2.4 用户指定口袋

用户可以通过以下方式指定口袋：

- 指定参考配体；
- 指定残基集合；
- 指定空间坐标或区域；
- 指定结构中的已知口袋。

Agent 应核验指定信息是否与当前受体一致。

若指定口袋与当前受体结构不匹配，应先说明差异并请求用户确认，不得直接转换或覆盖口袋定义。

**口袋确认前，不得执行 `prepare_receptor`，包括预演。**

## 3. 受体准备与状态管理

### 3.1 受体准备前检查

受体准备前应检查：

- 当前受体是否已确认；
- 当前口袋是否已确认；
- 结构文件是否有效；
- 链和残基信息是否匹配；
- 是否存在缺失原子或残基；
- 是否存在需要处理的配体、溶剂或其他结构组分；
- 当前结构是否与既有产物一致。

如果上述信息不完整，应先解决问题，不得直接进入准备阶段。

### 3.2 受体准备预演

受体准备必须采用预演与正式执行两阶段机制。

首先调用：

`prepare_receptor(confirm=false)`

预演应展示：

- 拟删除或修改的结构组分；
- 受体准备参数；
- 盒子设置；
- 残基匹配情况；
- 结构处理中的潜在风险；
- 预期生成的产物。

预演结果仅用于检查和确认，不代表正式准备已经完成。

### 3.3 用户确认与正式准备

用户确认准备方案后，才能执行：

`prepare_receptor(confirm=true)`

准备参数应由用户选择或确认。

不得在用户未确认的情况下：

- 自动删除关键结构组分；
- 静默修改受体；
- 静默更改口袋；
- 使用未经确认的参数完成准备。

### 3.4 受体状态切换

当用户切换受体时，应更新当前任务状态。

需要检查：

- 原受体是否仍然适用；
- 原口袋是否需要重新定义；
- 受体准备产物是否失效；
- 对接结果是否仍可使用；
- DTA 或其他预测模型是否需要重新运行。

旧产物不得自动沿用到新受体。

## 4. 对接、打分与结果分析

### 4.1 配体来源与准备

对接前应明确配体来源：

- 已知活性配体；
- 用户提供的化合物；
- 数据库检索获得的分子；
- 生成模型产生的候选；
- 其他明确来源。

应记录配体的身份、来源和必要的结构信息。

对接前应检查：

- 配体结构是否有效；
- 化学结构是否与用户指定一致；
- 配体准备是否完成；
- 当前配体集合是否经过用户确认；
- 配体是否与当前任务目标匹配。

不得将未经核验的配体结构直接纳入正式对接。

### 4.2 对接前确认

正式对接前，应向用户明确说明：

- 当前受体；
- 当前口袋；
- 当前配体集合；
- 对接参数；
- 评分方法；
- 本次对接的目标；
- 预期生成的产物。

只有受体、口袋、配体集合及关键参数均已确认，才可以执行正式 docking。

### 4.3 对接结果统计

对接完成后，应汇总：

- 成功与失败的配体数量；
- 评分分布；
- 候选分子的排名；
- 结构质量或位姿异常；
- 失败原因；
- 结果文件及可视化入口。

应区分不同类型的失败：

- 配体准备失败；
- 受体准备失败；
- 对接程序执行失败；
- 评分失败；
- 结果解析失败；
- 位姿异常。

不得将技术失败直接解释为分子不具有活性。

### 4.4 结果写入与可视化

对接结果应通过项目提供的工具完成写入和展示。

必要时使用：

- `write_run`
- `open_viewer`

结果写入后，应确保其关联：

- 当前任务；
- 当前受体；
- 当前口袋；
- 当前配体集合；
- 对接参数；
- 评分结果。

对于具体位姿和结构描述，应提供可打开的结构产物。

### 4.5 Docking 与 DTA 的区别

Docking 与 DTA 应作为不同层次的证据使用。

Docking 主要用于：

- 评估结合位姿；
- 检查结构合理性；
- 识别潜在相互作用；
- 对候选分子进行结构过滤。

DTA 主要用于：

- 预测结合亲和力；
- 对候选分子进行模型层面的排序；
- 辅助筛选和实验优先级判断。

二者均不能直接替代实验数据。

### 4.6 DTA 流程

DTA 任务应遵循：

1. 明确预测目标及标签定义；
2. 检查数据来源和质量；
3. 确认受体、配体及标签对应关系；
4. 检查训练集与测试集划分；
5. 完成必要的模型拟合；
6. 执行预测；
7. 评估模型性能；
8. 分析预测结果及其不确定性。

若模型尚未完成必要拟合，不得将预测结果表述为有效的模型输出。

对于模型性能，应明确：

- 训练数据范围；
- 测试数据范围；
- 评价指标；
- 潜在数据泄漏风险；
- 适用范围。

### 4.7 对接分数与亲和力比较

对接分数应遵循以下比较原则：

- 同一受体；
- 同一口袋；
- 相同评分方法；
- 可比的对接设置；
- 一致的配体处理方式。

不同受体或不同口袋的 docking score 不应直接进行数值比较。

Docking score 不应直接解释为 IC50、Ki、Kd 或其他实验亲和力指标。

### 4.8 候选分子排序与解释

调用 `rank_candidates` 后，应解释：

- 排名依据；
- 关键评分指标；
- 结构差异；
- 可能的结合优势；
- 主要不确定性；
- 需要进一步验证的候选。

候选排名应作为筛选线索，而不是最终活性结论。

### 4.9 共同结构特征分析

调用 `common_features` 后，应说明：

- 共同子结构；
- 特征的计算依据；
- 特征与结合模式之间的关系；
- 是否存在潜在的结构–活性关系；
- 是否需要进一步验证。

不得仅根据少量候选的共同结构直接建立确定性 SAR 结论。

### 4.10 相互作用分析

相互作用分析应基于实际结构和计算结果。

需要区分：

- 结构中实际观察到的相互作用；
- 工具识别的潜在相互作用；
- 根据结构提出的机制假设。

对于关键相互作用，应提供具体残基、配体原子或结构位置。

不得仅凭 docking score 推断氢键、盐桥、疏水作用或其他相互作用。

### 4.11 结果解释与替代结合模式

对优先候选，应检查是否存在替代结合模式。

分析应考虑：

- 不同位姿；
- 不同口袋区域；
- 关键残基变化；
- 配体构象差异；
- 评分方法的局限；
- 结构证据是否支持当前解释。

避免仅依赖单一结合模式解释全部候选。

## 5. 开工前的项目盘点与起点推荐

### 5.1 盘点时机

当用户的研究意图已经明确，但尚未进入正式结构选择或筛选执行时，应调用：

`assess_campaign`

该步骤用于评估项目当前状态，并推荐合适的筛选起点。

它属于策略规划环节，不是新的用户确认点，也不能替代后续结构、口袋、受体准备和对接确认。

### 5.2 盘点目标

项目盘点应综合考虑：

- 受体侧信息；
- 配体侧信息；
- 已有实验数据；
- 已有结构数据；
- 已有模型及计算产物；
- 当前任务目标；
- 主要不确定性；
- 当前筛选资源和限制。

盘点结果应明确哪些信息已经具备，哪些信息仍需补充。

### 5.3 受体侧指标

受体侧盘点应考虑：

- 受体结构是否明确；
- 是否具有实验结构；
- 是否存在已知配体；
- 口袋是否已知；
- 口袋结构是否具有可靠证据；
- 是否存在关键机制信息；
- 是否存在多个可能的受体构象；
- 当前结构是否适合后续筛选。

### 5.4 配体侧指标

配体侧盘点应包括：

| 维度 | 盘点内容 |
|---|---|
| 已知活性配体 | 是否存在已验证配体及其来源 |
| 化学型 | 是否具有明确的活性化学型 |
| 配体数量 | 当前已知或可获取的配体规模 |
| 结构多样性 | 配体之间的化学空间覆盖情况 |
| 实验数据 | 是否具有 IC50、Ki、Kd 或其他活性数据 |
| 计算产物 | 是否已有对接、DTA 或其他预测结果 |
| 数据质量 | 是否存在重复、标签不一致或数据缺失 |

盘点时应区分真实实验数据与模型预测数据。

### 5.5 筛选起点推荐

根据盘点结果，推荐以下四类起点。

#### Narrow：已知化学型内的精细筛选

适用于：

- 已有明确活性配体；
- 活性化学型相对清晰；
- 具有可用于比较的参考结构或实验数据。

优先开展：

- 已知配体相似性分析；
- 化学型内扩展；
- 结构优化；
- 结合模式比较；
- 精细化候选筛选。

#### Expand：化学空间扩展

适用于：

- 已知活性化学型，但候选数量有限；
- 希望探索结构类似物；
- 当前配体覆盖不足。

优先开展：

- 2D 相似性筛选；
- 结构聚类；
- 形状相似性分析；
- 药效团筛选；
- 逐步扩展化学空间。

#### Mechanism：机制驱动筛选

适用于：

- 已知关键残基或结合机制；
- 已有明确的结构生物学证据；
- 希望探索具有特定相互作用特征的候选分子。

优先开展：

- 机制相关口袋分析；
- 关键残基约束；
- 结构特征筛选；
- 结合模式验证；
- 机制相关候选排序。

#### Expand：组外探索

适用于：

- 已知化学型无法充分解释目标；
- 现有配体空间覆盖不足；
- 希望探索新型化学结构；
- 已有筛选路径缺乏足够候选。

优先开展：

- 更广泛的化学空间探索；
- 多样性筛选；
- 结构或药效团约束；
- 多阶段筛选；
- 对潜在新型结合模式进行探索。

### 5.6 起点选择与改道条件

Agent 应根据当前证据推荐起点，并解释推荐依据。

当出现以下情况时，应考虑改道：

- 当前化学型缺乏足够活性证据；
- 已知配体无法覆盖目标口袋；
- 口袋定义存在重大不确定性；
- 当前筛选路径无法产生有效候选；
- 新证据支持不同机制；
- 当前模型或数据不适用于目标任务。

改道应说明：

- 当前路径的限制；
- 新路径的必要性；
- 预计增加的工作；
- 可能产生的新风险。

### 5.7 盘点结果的边界

`assess_campaign` 的输出是筛选策略建议，不是筛选结论。

盘点推荐不得：

- 自动选择受体；
- 自动确认口袋；
- 自动执行受体准备；
- 自动执行对接；
- 自动将候选分子纳入正式筛选；
- 替代用户对关键操作的确认。

## 6. 结果交付与异常处理

### 6.1 结果交付结构

最终结果应包含：

1. 研究目标；
2. 当前受体及结构来源；
3. 当前口袋及定义依据；
4. 配体来源和筛选范围；
5. 使用的方法与关键参数；
6. 主要计算结果；
7. 候选分子及排名依据；
8. 关键结构特征或相互作用；
9. 不确定性与方法限制；
10. 后续实验建议。

### 6.2 结果可追溯性

关键结果应关联：

- 原始结构；
- 受体准备产物；
- 口袋定义；
- 配体结构；
- 对接任务；
- 评分结果；
- 可视化页面；
- 实验记录。

不得只提供孤立的排名或分数。

### 6.3 异常处理

工具报错时，应：

1. 保留错误信息；
2. 判断错误属于输入、结构、参数、计算还是解析问题；
3. 检查当前任务状态；
4. 明确需要修复的内容；
5. 在必要时向用户请求确认；
6. 修复后重新执行对应步骤。

不得在工具失败后伪造成功结果。

### 6.4 实验结果回填

当用户提供实验结果时，应通过：

`record_assay`

记录实验数据及其对应关系。

实验记录应尽可能包含：

- 分子身份；
- 实验类型；
- 实验条件；
- 测量指标；
- 数值及单位；
- 数据来源；
- 与当前预测结果的关联。

实验数据应与预测结果明确区分。

### 6.5 交付原则

最终交付应回答三个核心问题：

1. **筛选结果是什么？**
2. **为什么这些候选值得进一步研究？**
3. **下一步如何验证当前假设？**

交付应形成可检验的实验假设，而不是仅提供分子排名。
