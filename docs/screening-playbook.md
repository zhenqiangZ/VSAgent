# 筛选细则（`AGENTS.md` 的展开）

`AGENTS.md` 是门禁与许可，四十来行；这份是它后面那些「怎么做」。
**讲到具体数字或具体参数之前读对应那一节**——不读就写，写出来的多半是编的。

模型读它的方式是 `read`：`AGENTS.md` 里每一道门禁末尾的「细则 §N」就是指向这里的。

---

## §1 结构

### 1.1 意图清楚之后，先把蛋白讲清楚

身份、物种、家族、功能一句话、已知结合位点或催化残基、相关突变与异构体；再说清它
「对什么敏感」——已报道的活性分子分几类、每类的代表分子与活性量级、哪些是共价或
别构、哪些只是早期苗头。

给用户的一段话必须包含：蛋白是谁、位点在哪、已知活性分子分几类、每类代表分子与
活性量级。然后问：你想筛的是哪一类？有没有必须保留或必须避开的骨架？
用户没有给出方向之前，不要往下走。

### 1.2 取证顺序：先查本地，再查文献与网页，最后才用先验知识

讲到**具体数字**（活性量级、IC50/Ki、临床阶段、突变影响、选择性倍数）时，
不能只凭先验知识。按下面这个顺序取证，**命中就停**，不要每条都走到底：

1. **`search_corpus`（免费、离线）**：本地语料库里有用户导入的文献与之前搜过的网页。
   中文提问也能命中英文文献，不必先翻成英文。命中相关片段就用它的引用号
   （`doc#…` / `web#…`），要读上下文用 `read_source`。
2. **本地没有、或命中的都不相关**：要**已发表文献**用 `search_literature`（PubMed，免费）；
   要**最新进展、厂商资料、指南**用 `search_web`（计费，约 0.005 元/次，本会话前 10 次不问）。
   联网搜到的结果会自动进本地语料，同一个 query 再搜不花钱。
3. **都查不到**：才用先验知识，并逐条标注「先验知识，未核验」，同时说明
   「本地语料与 PubMed 都没有查到」——**不要**把查不到写成「没有这回事」。

三个工具分在 `corpus` / `websearch` / `literature` 族，第一次用之前 `load_tools` 装上，
**一次把这一段要用的族装完**（装一次改一次工具清单，下一步的缓存会失效）。

**不要变成检索远征**：只查要写进结论的那几个数；一次取证最多两轮
（本地一次 → 不够再联网或 PubMed 一次），查不到就如实说，不要换着关键词反复搜。

### 1.3 候选结构：先给假设，再核对

先用先验知识说出：这个蛋白可能的口袋、每个口袋的代表配体、以及你认为对应的 PDB 编号。
说的时候必须原样带上这句：「以下是待验证的假设，未经核对，不作为依据。」
这些编号与坐标**不许写进登记表、不许当成 handle 用**，后面一律重新取证。

以这一组 PDB 编号为清单取证。**不要**改成用该蛋白的 UniProt 编号去检索复合物：
那种检索只返回「带配体的已发布复合物」，能覆盖到的口袋远不如先验清单宽。

两道核对，按顺序做，缺一不可：

1. **编号是不是真的存在。** 逐个确认它确实是已发布的条目。不存在的剔除，
   并在报告里列出来，不要静默丢掉。
2. **序列是不是受体序列。** 把取回来的坐标里各条链的序列与该蛋白的序列比对，
   对不上的条目剔除，同样在报告里列出来。

两道都通过的条目才进入下一步。核对结果要逐条报给用户：通过了哪些、剔除了哪些、
每一条为什么。

## §2 口袋

### 2.1 叠合与算口袋

· 以**受体自己**为参考系，把各份复合物的坐标都叠合到它上面，逐份报出 rmsd。
  拿受体当参考系、而不是拿第一份复合物：口袋的中心最后要当盒子用，而盒子是在
  受体的坐标系里——拿复合物当参考系，算出来的中心对不上受体。
· rmsd 明显超过阈值的说明不是同一个位点、或不是同一构象，要单独说明，不要混进去。
· 把叠合后的全部配体坐标聚成簇，逐簇圈出 5 埃以内的受体残基，算出中心。
· 每个口袋要说清：编号、中心、来自哪几个复合物与哪个配体、圈住了哪些残基、
  叠合 rmsd。**不要自己编 score**——实验定位没有打分这回事。

叠合、核对、算口袋这三步由**写运行目录那一个动作一并完成**：把编号清单交给它，
它逐个核对、叠合、算口袋，并把逐条结论一起返回。不要自己分头去做——分开做的话，
报出来的 rmsd 与页面上的口袋对不上。

### 2.2 展示

写成一份运行目录并给出结构页地址，让用户在看板上看口袋位置。

### 2.3 没有明确口袋时

按先验清单取证后仍然没有口袋时，转预测这一侧；这一步工具会自己做，不需要你决定。
两条路都拿不到就如实说明是「查了确实没有」还是「没查成」，这两者对用户的含义相反。

### 2.4 用户给的口袋

口袋一律以用户的选择为准，不是以你呈现的排序为准。用户给出的与呈现的不同时，
问清依据，并接受四种形式：

· 一个 PDB 编号（重新取该结构核对）
· 用户自己提供的结构文件（结构走 `import_structure`，配体走 `import_ligandset`，
  文献走 `import_documents`）
· 显式的盒子中心与边长（准备受体时手动给）
· 残基编号（`define_pocket` 的 `residues`，形如 `A:315,A:319`；盒子按残基包围盒算）

用户报残基编号时直接用第四种，不要请用户改写成前三种。

## §3 对接前的最后确认

· 用 `prepare_receptor` 先做一次预演（默认那次不写盘），把「会删掉哪些水与杂原子、
  盒子算在哪、哪些残基匹配不上」摆给用户看。
· 预演结果念给用户听，等用户说可以，再用 `confirm=true` 真正写盘。
· 参数是用户的选择：留哪条链、共晶配体用哪个、盒子要不要手动给、padding 多少，
  有分歧先问，不要自己定。
· 用户要换受体时用 `switch_receptor`，并说明换掉之后哪些已有产物不再适用。

## §4 对接

### 4.1 配体从哪来

· 用户自己给的库：`import_ligandset` 收 `.sdf` / `.sd` / `.smi` / `.csv`，然后
  `prepare_ligands`。先用 `confirm=false` 预演，把去重后的条数、性质范围、会截断到多少
  报给用户；用户说可以再 `confirm=true`。**不要不问就准备一整库。**
· ChEMBL 的活性/类似物结果：`search_actives` / `find_analogs` 产出的 ligandset 可以直接
  交给 `prepare_ligands`，同样先预演再确认。

### 4.2 先报参数，再问

调 `dock` 之前，把这几样摆给用户：

· 受体 handle 与口袋来源；
· 盒子中心与边长（从已准备受体的 `box.txt` 读出来，**不要自己算、不要自己改**）；
· 配体总数、本次 `limit` 取多少、还剩多少没处理；
· `exhaustiveness` / `num_modes` / `seed` / `cpu` / 单配体 `timeout`。

参数是用户的选择。用默认值也要说一句「按默认参数跑」，不要静默替用户定。
要换盒子就回 `prepare_receptor` 重跑；`dock` 的签名里没有盒子参数，这是刻意的。

单批可能跑很久：`limit` 个配体 × 单条 `timeout` 是最坏情况，先把这个量级说清楚。

### 4.3 结果怎么读

· 分数**越低越好**（kcal/mol）。只能在同一受体、同一盒子、同一套参数内比较，
  **不是结合自由能，不能跨靶点比较**。
· 必须报：可评分几个、转出 PDB 几个、失败几个、未处理几个；最佳分数与配体效率；
  失败原因（超时 / Vina 非零退出 / 没有结果 / 位姿转不出 PDB）。
· 区分「没筛出东西」与「没筛成」：前者是结果，后者是故障，对用户的含义相反。
· **不要自己编分数、不要手算排名、不要挑一个「看起来合理」的构象当结论。**
  所有数字来自 `dock` 的返回或 manifest。

### 4.4 上网页

对接结果要进运行目录，走：

```
write_run(receptor=..., docking=artifact#N)
open_viewer(run=artifact#M)
```

`write_run` 会把最佳 pose 复制进 `ligands/`、填 `molecules` 的分数与排名、
写 `provenance.poses`。**不要手动复制 pose 文件，也不要自己拼 meta.json。**
`write_run` 的 `docking` 与 `ligands` 二选一：前者已经带着配体集。

### 4.5 不要做的事

· 不要在受体或配体集还没 prepared 时调 `dock`；原始结构/原始配体集会被拒绝。
· 不要用对接分数替代实验活性，也不要把一次对接的排名当成「筛选结论」。
· 不要在一次结果里跨受体、跨盒子、跨参数比较分数。
· 不要为了「多跑几个」擅自把 `limit`、`exhaustiveness`、`timeout` 调到用户没同意的值。
