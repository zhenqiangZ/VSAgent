# 结构上网页（简要规划）

把「agent 拿到蛋白与配体 → 导出运行目录 → 常驻本地服务 → 网页看结构」这条链路做通。
本文件只说**要做什么**；为什么这么定、否决过什么、实测数据与踩坑记录在 `docs/web-viewer-plan.md`（详细稿）。

## 一、总目标

一句话：**给 agent 两个动作——「导出结构到网页」与「打开网页」，并把中间那条链路补齐。**

现在缺三段：登记表里的产物**出不去**（没有导出）、服务**不在包里**（冻结后脚本不在磁盘上）、
agent **开不了页面**（没有返回 URL 的工具）。

## 二、总体逻辑

```
  受体 handle（登记表）
        │
        ├─ P0 主来源：RCSB 属性搜该蛋白所有复合物 ─▶ 排序取前 N ─▶ 下载 ─▶ 取配体 ─▶ 圈口袋
        │                                                                    （空才往下走）
        └─ P1 副选：prankweb p2rank 预测（仅当 P0 为空）
                                    │
                                    ▼
  handle ──write_run──▶ runs/<id>/ + meta.json ──▶ 包内常驻服务 ──▶ 浏览器
                              │                          │
                       口袋 / 分子 / 来源            只读，绑 127.0.0.1
```

三条贯穿全篇的原则：

1. **数值不经过模型。** 距离、打分这类量，能算的现算、能给接口的取接口，
   **绝不接受模型传进来的数**——它算错时看上去很像对的。
2. **每个数都标来源。** 预测的、实验的、算出来的，写在 `source` 里，前端据此显示徽标。
3. **没有来源就留空。** 宁可不给，也不编一个「看上去合理」的值。

## 三、要做的事（八步）

### 1. 几何算法（纯函数，零依赖）
最短距离、口袋残基、配体聚类、配体中心、接触对。**不引化学依赖**，用现成的 `pdbtext` 坐标解析。
聚类用并查集（不是顺序贪心），配体之间「任一原子对」在阈值内即同簇。

### 2. P0 主来源：搜该蛋白的所有复合物 → 排序 → 下载 → 取真口袋
按 UniProt 用 RCSB 属性搜列出该蛋白**所有**带配体的已发布结构（ABL1 实测 69 个），
按分辨率/方法/配体像真配体排序取前 N（默认 12）下载，筛掉水与缓冲液后聚类成口袋，
跨复合物合并（中心 6 Å 内算同一处），并记下每个口袋跨了哪几个复合物。
**这是主要来源**：口袋是测出来的，用户点开能看到「谁做过什么复合物」。

### 3. P1 副选：口袋预测（仅当 P0 一个复合物都没有）
从 **prankweb.cz** 按 PDB 条目取 p2rank 口袋：残基集合 + 打分 + 置信度 + 三维中心。
带状态轮询、磁盘缓存、失败降级。**关键**：接口对任何编号都返回「已排队」，**必须看 `status` 字段、
不能看 HTTP 码**。给的是 PDB 作者编号，不需要换算。
**只有 P0 为空才走这里**——有实测事实就不叠加预测。

### 4. `write_run`：把 P0/P1 的结果写成一个运行目录
从受体坐标里取非水杂原子 → 按口径筛掉水/修饰残基/金属离子/缓冲液 → 聚类成口袋。
`write_run` 把受体、配体、口袋、来源写成一个运行目录，登记成 `artifact`。
**顺序固定：先 P0，P0 空才转 P1**；返回里报清「搜到几个、用了几个」与三态
`origin = "complex" | "predicted" | "none"`。

### 5. 搜索工具（RCSB + 文献，只读）
两个给模型用的工具：`search_pdb`（RCSB 文本/属性搜 + 批量取配体）、`search_literature`（PubMed）。
**返回候选清单，不带归类判断**；**搜索结果不写盘、不进 `meta.json`**。
搜索是「找线索」，不是「出数据」——P0 用的是可复现的属性搜，不是开放式文本搜。

### 6. 包内服务
把 `tools/serve_web.py` 的路由与 JSON 形状搬进 `core/web/routes.py`（**唯一真相**），
`serve_web.py` 改为导入它。服务跑在应用进程的后台线程里，随应用启停，端口 8860 起自动避让。

### 7. 接线与应用集成
`app.py` 启停服务；`open_viewer` 工具返回 URL（默认不擅自开浏览器）；
装配四个新工具；`write_run` 进 Plan 禁止名单（它写盘），三个只读工具放行；
前端加 `source` 徽标（**本轮唯一动前端处**）。

### 8. 端到端与回归
三种情况各走一遍：**P0 有货**、P0 为空但有预测、两者都不可用。
两层断言 + 禁用字 + 判据五段 + **重新打包 + 成对抓帧七帧**。
旧演示目录 `runs/1iep-demo/`（旧字段形状）必须仍能打开。

## 四、产出

**新增**：`export.py`（工具 + 几何）、`complexes.py`（P0 复合物搜/排/下）、`pockets.py`（三层来源）、
`prankweb.py`（预测客户端 + 缓存）、`rsearch.py` / `literature.py`（搜索）、`viewer.py`（开页面）、
`core/web/{routes,service}.py`（服务）。

**修改**：`app.py`（启停服务）、`all_tools.py`（装配，工具 11 → 15 个）、`permission.py`、
`prompt.py`、`tools/serve_web.py`、`opencode_tui.spec`（`datas` 加 `web/` 静态资产）。

**前端只动一处**：口袋组件加 `source` 徽标，且 `provenance.pockets` 新旧两种形状都认。

## 五、本轮不做

对接与真实打分、自己跑 p2rank/fpocket、金属离子参与口袋、P0 的自定义筛选、
跨结构的预测一致性统计、按文献人工整理口袋清单、自建结构的预测上传、鉴权与多人访问。

## 六、四个已定的口径（照着做，不再讨论）

- **口袋来源三层，优先级固定**：**P0 = 该蛋白的复合物结构（主来源）**，
  P1 = p2rank 预测（**仅当 P0 为空**），P2 = RCSB 现成距离（作 P0 的距离来源与交叉验证）。
- **配体口径**：只算大分子有机配体；水 / 修饰残基 / 金属离子 / 常见缓冲液四类排除。
- **服务形态**：包内常驻、随应用启停、只绑 `127.0.0.1`。
- **零散参数全部按默认拍定**（详细稿 §7 有 11 条）：`web/` 整目录进包、`VSA_WEB_PORT` 默认 8860、
  `open_viewer` 进 Plan 白名单、`CLUSTER_GAP = 4.0 Å`、P0 下载上限 **N = 12**、
  prankweb 同步查 **15 秒**超时、`POCKET_RADIUS = 5.0`、缓存都在 `~/.opencode_tui/` 下。
  **执行时不再回头讨论。**
