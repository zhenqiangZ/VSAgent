# 筛选细则

> 角色：现行设计（`AGENTS.md` 四个确认点的展开）
> 状态：随代码更新，最后核对 2026-11-06
> 配套：`design.md`（系统长什么样）、`history.md`（为什么这么定）、`reference.md`（判据）

`AGENTS.md` 是确认点与许可，四十来行。它四个确认点末尾写的「细则 §N」指的就是这一节的 §N；
讲到具体数字或参数之前，先读对应那一节。模型读它的方式是 `read`。

## §1 结构

**1.1 意图清楚之后，先把蛋白讲清楚。**

身份、物种、家族、功能一句话、已知结合位点或催化残基、相关突变与异构体；再说清它「对什么
敏感」——已报道的活性分子分几类、每类的代表分子与活性量级、哪些是共价或别构、哪些只是早期
苗头。

给用户的一段话必须包含：蛋白是谁、位点在哪、已知活性分子分几类、每类代表分子与活性量级。
然后问：你想筛的是哪一类？有没有必须保留或必须避开的骨架？用户没有给出方向之前，不要往下走。

**1.2 取证顺序：先查本地，再查文献与网页。**

讲到具体数字（活性量级、IC50/Ki、临床阶段、突变影响、选择性倍数），或者要介绍一个蛋白时，
都不能只凭记忆。按下面顺序取证，命中就停，不要每条都走到底：

1. `search_corpus`（免费、离线）：本地语料库里有用户导入的文献与之前搜过的网页。中文提问也能
   命中英文文献。命中相关片段就用它的引用号（`doc#…` / `web#…`），要读上下文用 `read_source`。
2. 本地没有、或命中的都不相关：要已发表文献用 `search_literature`（PubMed，免费）；要最新进展、
   厂商资料、指南用 `search_web`（计费，约 0.005 元一次，本会话前 10 次不问）。联网搜到的网页
   当场进本地语料库，同一句 query 再搜不花钱；写完这一步再用 `search_corpus` 检索一遍，拿引用号
   引用刚查到的内容——介绍里每个数字都要能指到一条来源。
3. 都查不到：如实说「本地语料与 PubMed 都没有查到」。不要把查不到写成「没有这回事」。

三个工具分在 `corpus` / `websearch` / `literature` 族，第一次用之前 `load_tools` 装上，
一次把这一段要用的族装完（装一次改一次工具清单，下一步的缓存会失效）。

不要变成检索远征：只查要写进结论的那几个数；一次取证最多两轮（本地一次 → 不够再联网或
PubMed 一次），查不到就如实说，不要换着关键词反复搜。

**1.3 结构全景：先铺开分母，再谈候选。**

用户没有点名结构时，先调 `survey_structures(accession=…)`：它把这个靶点在 RCSB 登记的全部实验
结构取回来，按共晶配体分组，每组给套数、最佳分辨率与代表条目；聊天里是摘要，全表在
`#/survey/<id>` 页面里（地址用 `open_viewer` 取）。这一步给的是分母——这个靶点被研究到什么程度、
有哪些配体结合过——不是候选清单，也不是结论。

先验知识仍然要说：这个蛋白可能的口袋、每个口袋的代表配体、你认为对应的 PDB 编号。说的时候
必须原样带上这句：「以下是待验证的假设，未经核对，不作为依据。」。候选要落在全景里的条目上；
全景里没有的编号单独标出来，说明它是记忆里的、待核对。

只按 UniProt 铺开有一个已知的盲区：它只返回已沉积的结构。文献里有、但没有解出结构的口袋
（别构位点、未成药的浅槽）不会出现在里面。所以全景之后仍按 1.2 查一遍文献，把「有结构」与
「只有文献」两类位点分开写。

两道核对，按顺序做，缺一不可：

1. 编号是不是真的存在。逐个确认它确实是已发布的条目。不存在的剔除，并在报告里列出来，
   不要静默丢掉。
2. 序列是不是受体序列。把取回来的坐标里各条链的序列与该蛋白的序列比对，对不上的条目剔除，
   同样在报告里列出来。

两道都通过的条目才进入下一步。核对结果要逐条报给用户：通过了哪些、剔除了哪些、每一条为什么。

## §2 口袋

**2.1 叠合与算口袋。**

- 以受体自己为参考系，把各份复合物的坐标都叠合到它上面，逐份报出 rmsd。拿受体当参考系、而不是
  拿第一份复合物：口袋的中心最后要当盒子用，而盒子是在受体的坐标系里——拿复合物当参考系，
  算出来的中心对不上受体。
- rmsd 明显超过阈值的说明不是同一个位点、或不是同一构象，要单独说明，不要混进去。
- 把叠合后的全部配体坐标聚成簇，逐簇圈出 5 埃以内的受体残基，算出中心。
- 每个口袋要说清：编号、中心、来自哪几个复合物与哪个配体、圈住了哪些残基、叠合 rmsd。
  不要自己编 score——实验定位没有打分这回事。

每处口袋都要给一份画像，工具已经把它算在口袋对象里（`profile`）：

| 项 | 内容 | 怎么来的 |
| --- | --- | --- |
| 配体 | 代号、重原子数、元素组成、伸展尺寸 | 数配体原子 |
| 壁 | 芳香 / 疏水 / 极性 / 带电各几个残基、最近的那个残基与距离、3.5 埃内的几个 | 按残基名分类，距离现算 |
| 判断 | 一句「窄长、以疏水壁为主、四周围得紧」这样的话 | 由上面两组数得出 |

转述给用户时把画像一起说，不要只报中心与残基数。画像里没有分数，也不要给它配一个。

脂质、磷脂、去垢剂不算配体，算口袋之前就剔掉，排除个数与原因要跟着结论一起说
（`detect_pockets` 的输出里是「筛掉的杂原子组」那一行；运行目录里是
`provenance.pockets.excluded`）。判据是四条全中：碳数 ≥ 8、极性原子（N/O/S）≤ 2 或含磷、
重原子 ≥ 16、包围盒最长边 ≥ 16 埃；另有一份去垢剂代号名单。只看元素会把类固醇药物一起筛掉，
所以最后那条「伸展长度」不能少。

叠合、核对、算口袋这三步由写运行目录那一个动作一并完成：把编号清单交给它，它逐个核对、叠合、
算口袋，并把逐条结论一起返回。不要自己分头去做——分开做的话，报出来的 rmsd 与页面上的口袋
对不上。

**2.2 展示。** 写成一份运行目录（`write_run(view=pockets)`），再用 `open_viewer(pocket=…)`
取结构页地址，让用户在看板上看口袋位置。地址要直接打开选定口袋的局部视图；消息里同时给口袋
编号、画像与地址，不要用残基表代替页面。

**2.3 没有明确口袋时。** 按先验清单取证后仍然没有口袋时，转预测这一侧；这一步工具会自己做，
不需要你决定。两条路都拿不到就如实说明是「查了确实没有」还是「没查成」，这两者对用户的含义
相反。

**2.4 用户给的口袋。** 口袋一律以用户的选择为准，不是以你呈现的排序为准。用户给出的与呈现的
不同时，问清依据，并接受四种形式：

- 一个 PDB 编号（重新取该结构核对）
- 用户自己提供的结构文件（结构走 `import_structure`，配体走 `import_ligandset`，文献走
  `import_documents`）
- 显式的盒子中心与边长（准备受体时手动给）
- 残基编号（`define_pocket` 的 `residues`，形如 `A:315,A:319`；盒子按残基包围盒算）

用户报残基编号时直接用第四种，不要请用户改写成前三种。

## §3 对接前的最后确认

- 用 `prepare_receptor` 先做一次预演（默认那次不写盘），把「会删掉哪些水与杂原子、盒子算在
  哪、哪些残基匹配不上」摆给用户看。
- 预演结果念给用户听，等用户说可以，再用 `confirm=true` 真正写盘。
- 参数是用户的选择：留哪条链、共晶配体用哪个、盒子要不要手动给、padding 多少，有分歧先问，
  不要自己定。
- 用户要换受体时用 `switch_receptor`，并说明换掉之后哪些已有产物不再适用。

## §4 对接

**4.1 配体从哪来。**

- 用户自己给的库：`import_ligandset` 收 `.sdf` / `.sd` / `.smi` / `.csv`，然后 `prepare_ligands`。
  先用 `confirm=false` 预演，把去重后的条数、性质范围、会截断到多少报给用户；用户说可以再
  `confirm=true`。不要不问就准备一整库。
- ChEMBL 的活性或类似物结果：`search_actives` / `find_analogs` 产出的配体集可以直接交给
  `prepare_ligands`，同样先预演再确认。

**4.2 先报参数，再问。**

调 `dock` 之前，把这几样摆给用户：

- 受体 handle 与口袋来源；
- 盒子中心与边长（从已准备受体的 `box.txt` 读出来，不要自己算、不要自己改）；
- 配体总数、本次 `limit` 取多少、还剩多少没处理；
- `exhaustiveness` / `num_modes` / `seed` / `cpu` / 单配体 `timeout`。

参数是用户的选择。用默认值也要说一句「按默认参数跑」，不要静默替用户定。要换盒子就回
`prepare_receptor` 重跑；`dock` 的签名里没有盒子参数，这是刻意的。

单批可能跑很久：`limit` 个配体乘以单条 `timeout` 是最坏情况，先把这个量级说清楚。

**4.3 结果怎么读。**

- 分数越低越好（kcal/mol）。只能在同一受体、同一盒子、同一套参数内比较；它不是结合自由能，
  不能跨靶点比较。
- 必须报：可评分几个、转出 PDB 几个、失败几个、未处理几个；最佳分数与配体效率；失败原因
  （超时 / Vina 非零退出 / 没有结果 / 位姿转不出 PDB）。
- 区分「没筛出东西」与「没筛成」：前者是结果，后者是故障，对用户的含义相反。
- 不要自己编分数、不要手算排名、不要挑一个「看起来合理」的构象当结论。所有数字来自 `dock`
  的返回或 manifest。

**4.4 上网页。**

```
write_run(receptor=..., docking=artifact#N, affinity=artifact#K, interactions="top")
open_viewer(run=artifact#M)
```

`write_run` 会把最佳位姿复制进 `ligands/`、填 `molecules` 的分数与排名、写 `provenance.poses`；
给了 `affinity` 还会写 `molecules[].affinity_pk` 与 `provenance.affinity`；给了 `interactions`
会给每个写入的位姿算接触与几何氢键，并对前 8 个算 PLIP 指纹。不要手动复制位姿文件，也不要自己
拼 `meta.json`。`write_run` 的 `docking` 与 `ligands` 二选一：前者已经带着配体集。

**4.5 不要做的事。**

- 不要在受体或配体集还没 prepared 时调 `dock`；原始结构与原始配体集会被拒绝。
- 不要用对接分数替代实验活性，也不要把一次对接的排名当成筛选结论。
- 不要在一次结果里跨受体、跨盒子、跨参数比较分数。
- 不要为了「多跑几个」擅自把 `limit`、`exhaustiveness`、`timeout` 调到用户没同意的值。

**4.6 亲和力打分（DTA）。**

顺序：

1. 受体准备时保留与选定口袋对应的共晶配体；微调的口袋从这里截出。
2. `search_actives` 取带 pChEMBL 的配体集。少于 40 个化合物不做微调，只走对接单路。
3. `fit_affinity(confirm=false)` 预演，报样本量、pK 范围、训练与验证切分、5–10 分钟耗时。
4. 用户确认后 `confirm=true` 训练，产出 `kind=model` 的产物。
5. 对接完成后，`score_affinity(model=artifact#M, ligands=对接产物)`，默认前 50 条。
6. `write_run(docking=…, affinity=…)` 把两路分数写进同一份运行目录。

读法：

- pK 越高越好，dock 的 kcal/mol 越低越好；两种分数不能直接比大小。
- 只对训练时的口袋有效；换口袋或换受体要重训，旧模型作废。
- 40–100 个活性时排序力有限：回顾性曲线是 100 个 → ρ 0.04、300 个 → 0.18、726 个 → 0.39。
- 报样本量与验证指标；RMSE 不代表排序力。
- 两路名次一致与背离的分子都要说，背离的分子往往是最值得看的一批。

**4.7 相互作用。**

`write_run(docking=…, interactions="top")` 是默认：所有写入的位姿算几何接触与几何氢键，
前 8 个再加 PLIP；`"all"` 给全部位姿加 PLIP；`"none"` 不算。结构页的分子模式会在三维里画
作用线，侧栏列类型、残基、原子、距离、角度。

PLIP 没算成时，几何接触与几何氢键照画，并写明盐桥、π 堆积、卤键、水桥、金属配位这几类没有算。
不要在消息里贴一张残基距离表让用户自己还原三维；三维页是主件。

## §5 开工前的盘点

`assess_campaign` 常驻，写在「意图明确、开始选结构」那一步之前。它自己查 UniProt 与 ChEMBL，
按下面两张表判定的量给出全部候选起点与一条推荐。

受体侧：

| 量 | 取哪来 | 阈值 | 为什么 |
| --- | --- | --- | --- |
| 结构可用性 | `fetch_target` 的 `pdb_count` / `pdb_structures[].resolution` | ≤3.0 Å 可用；3.0–3.5 Å 只能定口袋轮廓；>3.5 Å 或没有结构不可用 | 3.0 Å 是侧链与配体位置能解释的下限 |
| 共晶配体 | `fetch_structure` 的返回、`detect_pockets(sources=ligand)` | ≥1 个算有 | 共晶配体是唯一能直接定口袋的证据 |
| 口袋唯一性 | `detect_pockets` 返回几处 | ≥3 处，或 `ligand` 来源为空，算不唯一 | 三处以上必须上网页让用户看 |

无实验结构时用 AlphaFold 顶替，但要多看一项：口袋 8 Å 内残基的 pLDDT。过半低于 70 时，这套
模型只能回答「哪一侧更亲脂」，不能回答「配体怎么摆」。

配体侧：

| 量 | 取哪来 | 阈值 | 为什么 |
| --- | --- | --- | --- |
| 活性条数 | `search_actives`，pChEMBL ≥ 7，按 InChIKey 去重取最强 | ≥20 多；10–19 少；<10 不够 | 10 是参考集标 `too_small` 的线 |
| 最大骨架组 | `scaffold_analysis`（组内 ≥3 才计） | ≥5 有成型系列 | 一个系列要能拿出五个同骨架分子 |
| 骨架组数 | 同上 | ≥3 组算化学型分散 | 分散时换骨架从最大那组起手 |
| SAR 密度 | `matched_pairs` 里 ΔpChEMBL ≥2 的对数 | ≥5 对算密 | 两个数量级差值才有信息 |
| 抗靶数据 | 抗靶 `search_actives` 按 InChIKey 求交集 | ≥1 个共有分子才算有选择性数据 | 没有共有分子就没有选择性比 |

四类起点逐条判适用，条件不互斥，全部返回，再按「同系物优化 → 换骨架 → 配体侧建模 →
借邻近受体」的优先级给一条推荐。推荐不等于结论，模型要比证据、比成本、比能区分什么：

| 盘点结果 | 起点 | 这一轮写下的假设 | 改道条件 |
| --- | --- | --- | --- |
| 结构可用、活性 ≥20、最大骨架组 ≥5 | 同系物优化（narrow） | 已知活性共享 X 骨架，S1 壁上以疏水接触为主；在最大骨架组内算匹配分子对 | 参考集 <10 条，或最大骨架组 <5 |
| 结构可用、活性 <20 或最大骨架组 <5 | 换骨架（expand） | 存在已知骨架之外的可结合化学型；形状与药效团筛一个库 | 四路叠合后口袋仍不唯一，交用户选 |
| 结构不可用、活性 ≥10 | 配体侧建模（mechanism） | 活性由 X 骨架锚在 Y 残基上决定；去掉该锚定基团的类似物实测 | 口袋残基 pLDDT 过半 <70 |
| 结构不可用、活性 <10 | 借邻近受体（expand） | 邻近受体 Z 的配体库里有本靶点的起点 | 邻近受体也没有小分子配体 |
