## 一、上下文与事件层

### 1.1 上下文从「裁剪历史」改成「按层装配」（2026-10-07）

- **约束**：旧实现只有 `PREFIX + RECENT` 两层，外加一段直接拼在 `system` 之后的常驻记忆与一段
  隐式摘要；`RECENT` 的淘汰单位是消息，`tool_call` 与结果会被切开，部分服务端直接回 400。
- **做法**：分七层，固定顺序 `PREFIX → MEMORY → TASK → EVENT → RECENT → EVIDENCE → HISTORY`；
  交互组原子；预算先扣工具定义与输出预留；降级链固定，装不下报错不截断。
- **依据**：`temperature` 与注意力随 token 增长被稀释；前缀字节稳定才能命中 prompt cache。
- **判据**：`check_context_budget`、`check_context_metrics`；正常路径下 `system` 逐字节不变。

### 1.2 前缀与易变信息分家（2026-10-07）

- **约束**：`build_system_prompt` 混装稳定段与易变段，`Workspace.state_text` 带当前时间。
- **做法**：`system` 只放身份、纪律、平台、`AGENTS.md`；日期（只到天）、工作目录、状态目录进
  user 头；平台那句属于本机常量，留在 `PREFIX`。
- **读数**：前缀整段 4499 token（固定段 1592，规则 2890）。
- **判据**：`tools/check_prefix.py`——超预算、点名首步看不见的工具、枚举残留、字节不稳定都会红。

### 1.3 摘要退休，事件层接管（2026-10-28）

- **约束**：旧事件设计把「记录」挂在「压缩」上，1M 窗口不压缩，于是记录一次都没触发；同一次会话
  里 `summary_upto = 4`，之后 33 步既不在摘要里也不在事件里。
- **做法**：内核每步自动记 Step，主题结束自动封存，标题与结论可由 `close_topic` 给，不给就用本地
  拼的那份；原文一条不删，靠 `Step` 上的位置取回。摘要只留「首轮就溢出」的兜底。
- **读数**：37 步会话上下文从约 800K 降到约 460K（−35%）。
- **判据**：`check_topic_views()`、`event-log` 组；三条不变式见 `design.md` §4.3。

### 1.4 主题边界改成位置（2026-11-05）

- **约束**：`close_topic` 的切点落在一条 assistant 消息中间，消息下标切不出轮中途的边界。
- **做法**：切点记 `(message_index, part_index)`；装配时 `RECENT` 从最后一条事件的切点开始；
  `Turn.part_start` 用同一个口径。
- **代价**：`Event.start` / `end` 两个旧字段的读者要一起改（网页分段、召回、界面主题卡）。
- **判据**：`check_topic_views()` 里「切点落在消息中间」的那几条。

### 1.5 七条不变量（v2 重构，2026-10-25 起）

覆盖连续、事件边界、记忆唯一有效值、证据有源、预算按剩余额度填满、压缩可逆、无事件时行为不变。
七条写在 `design.md` 的对应小节里，判据分散在 `check_context_*` 与 `event-log` 组。

### 1.6 取回按步、默认不带推理、限额按 token（2026-11-07）

- **约束**：`read_turn` 用 `render_range(turn.message_index, turn.message_index + 1)` 铺原文，
  而一条 assistant 消息装着一整轮的所有步。`ses_0023` 里 `turn 23/24/25` 三次调用的输出
  完全相同（各 9,699 字符），`turn 27–29` 都是 115,732 字符——查一步等于把十几步倒出来。
  13 次 `read_turn` 共 123,256 字符，占全部工具输出的 45%；加 6 次 `recall_event`
  共 146,057 字符，占 53%。这些输出里 29.1% 是思考过程。
- **做法**：`Turn` 增加 `step_no` 与 `part_end`，`split_turns` 按 `step_segments` 的段递增编号，
  `read_turn` 的入参从 `turn` 改成 `step`，渲染区间收窄到一段；`render_part` /
  `render_range` / `render_between` 增加 `with_reasoning`，三个取回入口默认关闭；
  两个工具共用 `page_lines()`，按 `estimate_tokens` 截断，单次 4,000 token。
  归档占位与省略清单从 `turn N` 改成 `step N`，同一段只列一行。
- **依据**：`placeholder_stale_reasoning()` 已经把跨轮推理换成占位符，注释里记着 37 步会话中
  推理占可见正文 62%。取回要回答的是「哪个 handle、哪个数字、哪一步失败」，这些在工具输出与
  结论里。推理里唯一值得留的是「为什么放弃某条路」，改由 `close_topic` 的结论承载。
- **读数**：改后 `read_turn` 前 12 步的输出在 78–3,220 token，逐次重放不再出现同一段内容。
- **判据**：`event-log`、`tool-clear`、`context-budget` 三组；`.probe/verify_recall.py`
  重放 `ses_0023`，检查输出里没有 `[思考]`、单次不超预算。

### 1.7 收束阶段与主题预算（2026-11-07）

- **约束**：`ses_0023` 最后一轮走满 24 步。前 21 步被 `close_topic` 封成 `evt_0009`，
  剩下 3 步被轮末封成 `evt_0010` 并标成 `exhausted`：界面把失败归到最后 3 步，
  而那 3 步本身没有问题。模型写出的收尾总结是一份完整报告，还向用户要 A/B 选择，
  读起来像任务做完了。`evt_0009` 走到 21 步时，尾部提示已经出现，模型没有收。
- **做法**：装配时把「本轮还剩 K 步」写进尾部提示；剩 3 步进入收束阶段，
  `write_run` / `close_topic` / `task` / `read_turn` / `recall_event` 之外的调用直接拒绝；
  这一阶段的整步失败不计进 `MAX_FAILED_STREAK`；当前主题 20 步且最近 4 步没有新产物时，
  内核自己封存并以 `EXIT_TOPIC_FULL` 结束这一轮；整轮停因写 `Session.last_exit_reason`，
  FOCUS 复述带上一轮停因与最后一个事件的 `handoff`。
- **依据**：只说「已经走了几步」时模型看不出还剩多少，不会为收尾留额度；按「一轮 24 步」
  计数也表达不了「一个主题做了多久」。
- **判据**：`loop` 组新增两条——主题 20 步无产物时 `last_exit_reason` 为 `topic_full` 且留下事件；
  收束阶段的拒绝不把整轮改判成 `tool_failed`。

### 1.8 会话标题由模型设置一次（2026-11-07）

- **约束**：TUI 新建会话固定叫 `New Session`，本机 24 个会话里 23 个是这个名字；
  网页端只取首句前 40 字，模型在 `close_topic` 里给的主题名用不上。
- **做法**：`Session.title_source` 记四个来源（`default` / `placeholder` / `auto` / `user`）；
  提交时 `set_placeholder_title()` 写首句；`close_topic` 增加可选 `session_title`，
  第一条事件封存时替换一次，之后不再改；`/rename` 写 `user`。
- **取舍**：旧状态文件分不清标题是手改还是首句截的，一律按 `user` 读回。宁可少改一次，
  也不能把用户起的名字覆盖掉。
- **判据**：`event-log` 的封存用例与 `models` 的读回用例；`/rename` 后自动改名不再生效。

### 1.9 主题标题与结论的本地规则（2026-11-07）

- **约束**：`ses_0023` 的 10 条事件里 6 条是本地标题。`evt_0006` / `evt_0007` / `evt_0008`
  的标题都是「A」——用户那几轮只回了一个字母，`_local_title` 把用户原话直接当标题；
  `evt_0005` 与 `evt_0010` 退化成「工具：… 等 N 个」。结论里还有一段工具名清单，
  占掉本应留给产物与数字的位置。
- **做法**：`_usable_ask()` 先判用户原话能不能当标题（少于 4 字、或没有汉字且不是多词就跳过），
  退到「产物 handle + 两个工具名」；`_local_summary()` 去掉「调用 X」，没有产物时补最后一步结果；
  `EVENT_SUMMARY_MAX` 600 → 1000；`CLOSE_TOPIC_AFTER` 3 → 2，第 8 步换成「先收一次再继续」。
- **依据**：标题要回答「这一段做成了什么」，工具名在流水里本来就有；结论要能直接接续，
  600 字写不下受体盒子、配体条数、最强活性与还差哪一步。
- **判据**：`event-log` 组里本地标题与本地结论的用例。

## 二、记忆

### 2.1 只做项目级事实（2026-10-07）

- **约束**：`AGENTS.md`（必须怎么做）、`TaskState`（这一轮做什么）、`Ledger`（手上有哪些产物）、
  上下文（这一步发什么）已经各占一块，记忆再混进去就分不清。
- **做法**：`FACT` 一种类型；存 `<工作目录>/.vsmemory/`；只记打分与筛选之前就存在的东西
  （受体、位点、配体库、参考活性物）。`PREFERENCE` / `RUN` / `RECIPE` 暂不做。
- **关键一条**：记忆里存路径加指纹，不存 handle——`receptor#1` 跨会话指向别的东西，写错了不会报错。
  写入时就拦：`remember` 借 `ledger.parse_handle` 判定，命中就拒。
- **判据**：`memory` 组与 `tools/eval_memory.py`。

### 2.2 失效而非删除（2026-10，第 13 节补充）

- **约束**：事实会更新，「这条还在不在」之外还得回答「这条还算不算数」「现在这事需要它吗」。
- **做法**：`superseded_by` / `supersedes` / `valid_from` / `valid_to` / `expires_at`；判同一主题
  只认两种情况——显式 `supersedes`，或共用引用加更新词。只共用引用不算同一主题。
- **常驻注入改成三段**（核心 / 相关 / 最近），上限从 2000 降到 1200，只统计显式 `recall` 的命中。
- **检索改成打分**：`(正文命中×2 + 引用命中×1) × exp(-age/90天)`，中文按 bigram 切词，不引词典。
- **容量**：磁盘 500 条，超出按「先失效、再最旧」归档，不删也不注入。
- **判据**：合成台账 `recall@5` 100%、stale 1.3%（见 `review.md` §2.3）。

## 三、工具链

### 3.1 领域工具分族装载（2026-10-27 起）

- **约束**：75 个工具的完整定义约 23K token，每一步都要发。
- **做法**：19 个核心常驻，56 个领域工具分 18 族由 `load_tools` 现装现用，装过之后每步 3.5K。
- **轮末卸载**：`prune_families()` 绑在轮末封存上，把这一轮没用过的族卸掉。八族全装时每步 12K，
  而典型一轮只用两三个族。两条边界：这一轮一个工具都没用过就不卸；这一轮刚装的族也不卸。
- **族的归属**：族记在 `Session.tool_families`，不记在注册表（注册表按根与子 agent 共享两份）。
- **判据**：`tool-family` 组；`hidden_names` 用排除集而不是白名单，新工具忘了登记族只会白占额度。

### 3.2 禁用清单与「看不见的工具」（2026-10-25）

- **约束**：`tools.toml` 里标关的工具不进注册表，而 `load_tools` 曾照着 `catalog()` 说「已装入」。
- **做法**：`load_tools` 减去 `registry.disabled`；整族被关时直接失败并说清原因；禁用文案不再
  教绕道。`missing_tool_reason` 认族，告诉模型先装哪一族。
- **读数**：这条当初一次误判烧掉 20 步、300K 输入（见 `review.md` §1.1）。

### 3.3 重试只在工具层一次（2026-10-25）

- **约束**：一次工具调用本身要几十秒，重试两次会把一次抖动拖成三倍等待。
- **做法**：`MAX_TOOL_RETRIES = 1`，只重试 `execute`，不重跑权限与钩子；重试用尽的文案写明
  「参数没有错，也不要用 bash 自己实现」。
- **判据**：`tool-retry` 组 13 条，含「普通 `ToolError` 不重试」与「可重试错误能穿出 domain 层」。

### 3.4 声明式依赖注入（2026-10-25 起）

- **约束**：工具要的东西越来越多（登记表、任务、证据、查看器、事件、注册表、子 agent）。
- **做法**：类属性声明，`Tool.execute` 统一注入；声明了却收到 `None` 返回「内核装配问题」，
  不抛出。工具层因此不必导入循环层。
- **理由**：在 `run()` 里自己断言再抛，会让每个工具各写一遍同一种错误文案。

### 3.5 外部数据源接入（2026-10-29）

- **约束**：查靶点、取结构、查文献、查化合物分散在四个服务，各自的错误语义不同。
- **做法**：四个新源（AlphaFold / Europe PMC / PubChem / Open Targets）加身份查询合并、化学探针、
  PLIP 指纹；网络出口只有一个 `http.py`，4xx 是永久失败，429/5xx/网络是可重试。
- **读数**：工具从 42 个增到 56 个（族 18）。

## 四、筛选流程

### 4.1 确认点从「介绍」改成「产物」（2026-10-30）

- **约束**：模型倾向一次讲完流程，用户没有真正做决定的机会。
- **做法**：四个确认点（结构、口袋、准备、对接与打分），每个都要用户点头；每个点末尾指向细则
  一节；呈现口袋要先写运行目录再给地址，没有地址不算交付。
- **依据**：`ses_0005` 最后一轮的口袋确认点暴露出「先对接再解释」的倾向。

### 4.2 产出单位改成假设（2026-10-30）

- **约束**：原来的产出是一张排名，排名回答不了「这条路线该不该走」。
- **做法**：`Hypothesis` 六要素；`test` 与 `expected` 必填，`expected` 必须含数值、阈值或对照；
  状态只由 `close` 与 `record_assay` 改；`write_run` 整份写进 `provenance.hypotheses`。
- **依据**：Roche 判据——交付物是想法，两条效用判据都不认排名本身。

### 4.3 开工前的盘点（2026-11-03）

- **约束**：单看受体侧或配体侧都会选错起点，三种错法都能在论文里找到。
- **做法**：`assess_campaign` 常驻，查 UniProt 与 ChEMBL，四项受体侧与五项配体侧的量，四类起点
  逐条判适用（不互斥），返回全部加一条推荐，每条带成本档与「能区分什么」。
- **一条硬约束**：配体侧活性要用 `spread=True` 取完整分布。默认只取最强的一段时，P00533 的 325 个
  分子全在 pChEMBL 9.49–11.00，Δ≥2 的匹配对恒为 0。
- **判据**：`campaign` 组；阈值表在 `screening-playbook.md` §5。

### 4.4 结构全景（2026-11-03）

- **约束**：宽泛问题发生在第一轮，那时一族都还没装。
- **做法**：`survey_structures` 常驻，按共晶配体分组铺开全部实验结构，标题点过名的配体排最前。
- **理由**：膜蛋白结构里胆固醇与磷脂按套数永远最多（Nav1.7 的 44 套里胆固醇 26 套），按套数排
  会把河豚毒素（3 套）挤进折叠行。
- **判据**：`survey` 组与网页 `#/survey/<id>`。

## 五、打分与亲和力

### 5.1 对接接三个力场，不接 AutoDock4 原程序（2026-10-31）

- **做法**：`dock(scoring="vina"|"vinardo"|"ad4")`。AD4 要先用 `autogrid4` 算图，图按「受体指纹 +
  盒子 + 原子类型」缓存在 `~/.vsagent/grids/`，盒子限 40 Å。
- **理由**：AD4 原程序 1–5 分钟一个配体，与批量筛选的形态冲突；AD4 力场已经通过 vina 拿到。
- **一条纪律**：三个力场的分数互不可比，描述里必须写。

### 5.2 微调产品化，代理模型不做（2026-10-29）

- **约束**：回顾性实验（`review.md` §4）证明预训练模型在靶点内是随机水平，靶点数据有用。
- **做法**：`fit_affinity` 用该靶点实测活性微调，产出 `kind=model`；`score_affinity(model=…)`
  用同一份权重与训练时的口袋推理；`write_run` 把两路分数写进同一份运行目录。
- **否掉的**：`fit_surrogate`（ECFP4 + GBDT 作为独立工具）。同一个需求已有 `fit_affinity`，
  再接一个只会让「用哪个分数」变成新问题。这条不要再提。
- **纪律**：pK 越高越好，dock 越低越好，两者不能比大小；只对训练时的口袋有效。

### 5.3 相互作用分两档（2026-11-01）

- **做法**：`write_run(interactions="top")` 给所有位姿算几何接触与几何氢键，前 8 个再加 PLIP；
  `"all"` 全算，`"none"` 不算。
- **理由**：PLIP 慢且偶尔失败，前 8 个之外的信息价值低；失败时几何结果照画，并写明盐桥、π 堆积、
  卤键、水桥、金属配位这几类没有算。
- **位置**：`domain/analysis.py` 与 `domain/sar.py` 共用同一套接触判定。

## 六、知识层

### 6.1 三路检索与参数定档（2026-10-23）

- **做法**：词法两路（`unicode61` + `trigram`）加向量一路（fastembed，384 维），RRF(k=60) 融合后
  补邻块、按「源 + 章节」聚组。
- **取舍**：不用分数相加（BM25 与余弦量纲不同，相加会让某一路单方面支配）；不引入 torch
  （onnxruntime 够用，exe 尺寸可控）。
- **调参**：五项里四项负结果，只采纳「每路 40 条」。读数见 `review.md` §3。
- **模型不自动下载**：255 MB 超打包预算，走「用户另装」这条路。

### 6.2 语料库是免费的本地通道（2026-10-23）

- **做法**：`search_web` 抓到的页面当场入库，同一句 query 再搜不花钱；文献导入走解析、切块、
  入库三步。
- **一条硬约束**：入库与重建共用 `index.chunks_for`。各写一份的话，重建出来的块与当初写进去的不
  一样，而「重建两次一致」这条判据正好抓不到这种漂移。

## 七、终端界面

### 7.1 配色收敛到一条灰阶加语义色（2026-11-03 起）

- **约束**：同时出现八种色相，没有任何东西看起来重要；同一类信息画两遍；标题栏、输入状态行、
  状态栏叠成 8 行常驻装饰。
- **做法**：九级灰阶加五个语义色；标题栏并入底部状态栏；输入区从 6 行压到 3 行。
- **读数**：100x30 实测消息区 22 行 → 26 行。

### 7.2 完成态用绿色（2026-11-06）

- **做法**：任务状态与主题标记的完成从灰换 `#4CAF50`；工具卡与步行的完成标记保持灰白。
- **理由**：消息区每个工具都挂绿勾，绿色就不再表示「这一段完成了」。

### 7.3 三栏与可调宽（2026-11-05、11-06）

- **约束**：会话树、主题清单、产物三份信息各占一块，挤在一栏里读不出层次。
- **做法**：左栏会话树加主题清单，中间消息区加输入框（同一栏，宽度由同一个 `1fr` 决定），
  右栏产物 / 子 agent / 用量；三条 1 列宽的界线可拖动、可按键调节，宽度存状态文件。
- **取舍**：拖动过程中不写盘，松手或按键调完写一次；画的时候按终端宽度再夹一次，不改设定。

### 7.4 折叠按锚点补偿滚动（2026-11-06）

- **约束**：点开一个主题会把正在看的那一段推开，贴底点击还会被拽回底部。
- **做法**：补偿量取锚点那一块组件的屏幕行差，改完放回原来的行；补偿之后不再贴底就关掉跟随。
- **理由**：按总高度差补偿只在变化的行全部位于视口上方时成立，点击折叠发生在视口里面。

### 7.5 状态分三层显示（2026-11-06）

- **约束**：用户按停之后主题仍写「进行中」，事后分不出做完的与被停下的。
- **做法**：Topic 的结局由 `_stopped_status` 先于封存判定；Step 状态从 Part 现场算；等待确认画成
  运行中的一个相位（`◐`），不新增第六种状态值。
- **不做的**：Topic Pending（要模型事先交出主题序列，而主题是封存时按位置切的）；Step Pending
  （与工具卡的 `○` 是同一份信息）；动画（只有秒表已经在跑，加旋转会与刚修好的滚动锚点互相干扰）。

## 八、网页端

### 8.1 从「两个页面」到三栏工作台（2026-11-05）

- **约束**：结构页与会话页各写一套导航，会话历史在网页上只能整份读。
- **做法**：hash router 四个页面；历史页三栏（会话树与主题、按主题分章的对话、产物），中间那栏
  三层折叠；工作空间页有输入框与最近任务。
- **一条纪律**：路由的真相只有 `routes.py` 的 `SPEC`，包内服务与独立脚本都从它取。

### 8.2 实时靠快照，不靠状态文件（2026-11-05）

- **约束**：`state.toml` 有几 MB，页面两秒拉一次会把它读穿。
- **做法**：`live/<sid>.json` 只装当前主题的那一截，500 ms 节流；页面只对运行中的行拉 `/live`。
- **顺序**：`finally` 里先存状态文件、再写 `running=false`，反了页面会拿到不含刚封存那一段的旧状态。

### 8.3 语料投递与任务提交都是转交（2026-11-05）

- **约束**：网页服务是应用进程里的一个线程，`SessionManager` 不是线程安全的。
- **做法**：写入口回 202 或 200，真正的动作交回应用的事件循环；独立运行的服务没有回调，明确回 503。
- **安全**：写入口要求 `X-VSA-Request: 1` 并校验 `Origin`；入库只认 inbox 里已有的文件名。

## 九、评测

### 9.1 五层评测方案（2026-10-30）

- **约束**：现有约 6,600 条断言全是实现正确性，回答不了「给一句话需求能不能做成」。
- **做法**：L0 回归、L1 任务级（60–100 任务）、L2 领域正确性（8–12 靶点）、L3 科学产出、L4 可靠性
  与安全；主张走「任务集 + 系统」双贡献。
- **三条最优先**：`http.py` 加记录与回放；`tools/eval_agent.py` 加首批 10 个 L1 任务；B3 脚本化
  基线。三条都还没做，现状见 `review.md` §6。

### 9.2 主指标按假设结案率（2026-11-02）

- **做法**：结案率、支持率、判不了比例、闭环延迟；不看回测 AUC。
- **理由**：AUC 量的是打分器排序能力，换个库就能刷高；「这条路线该不该走」与库无关。
  `inconclusive` 超过 30% 说明预期写得不够硬，先改 `hypothesis` 的描述。

## 十、工程与打包

### 10.1 原子写状态文件

- **约束**：分七段写回时读的人会拿到半截内容，而被截断在表边界上的那份内容仍是合法 TOML，
  解析成功说明不了完整。
- **做法**：同目录临时文件 → flush → `os.fsync` → 40 次 × 5 ms 重试换名。

### 10.2 路径不按 `__file__` 算

- **约束**：冻结之后 `__file__` 指向解包出来的临时目录，写进去的文献、索引与运行目录退出时一起
  消失，而每一步都返回成功。
- **做法**：`project_root()` 在源码运行时给仓根，打包后给启动目录。

### 10.3 DTA 单独一套环境

- **约束**：主仓 3.12，`pandas==1.5.3` 没有 cp312 轮子，MDAnalysis 要求 `numpy<2`。
- **做法**：`models/DTA/.venv` 单独装（3.10 + torch 2.2.1 + dgl 2.1.0），主仓一行 torch 都不
  import，工具起子进程；`models/DTA/` 整个目录不进版本控制，也不能放进 `vsagent/`（化学依赖判据
  会扫到 45 处顶层 import）。

### 10.4 CI 只有一条

Linux 上跑 `tests/test_agent.py` 与 `tests/test_smoke.py`，两份依赖都装。没有 Windows job；
`verify_exe.py` 需要 pywinpty，那条路还没有人验证过。

## 十一、已经否掉的做法

| 做法 | 否掉的理由 |
| --- | --- |
| `fit_surrogate` 代理模型工具 | 与 `fit_affinity` 是同一个需求，两个分数会变成新问题 |
| AutoDock4 原程序 | 每个配体 1–5 分钟，与批量筛选的形态冲突 |
| 主题 Pending 状态 | 要模型事先交出主题序列，而主题是封存时按位置切的 |
| 步 Pending 状态 | 与工具卡的 `○` 是同一份信息 |
| 全局展开所有工具卡 | 一次摊开几十张卡，滚动长度与每帧重排代价一起涨，下次打开还是展开的 |
| 界面动画 | 工具卡已有秒表，旋转会与滚动锚点互相干扰 |
| 向量库做记忆检索 | 条目只有几十到几百，索引与模型依赖换不来收益 |
| 自动抽取记忆 | 自动写错比不写更糟，写入只有 agent 显式与用户显式两条路 |
| 按分数相加融合检索 | BM25 与余弦量纲不同，某一路会单方面支配 |
| 在 LIT-PCBA 上刷 SOTA | 该基准已被审出泄漏，2,491 个 2D 相同阴性跨 train/val |
| 让评测依赖实时网络 | 同一任务跨月复现不了，数字不可复算；要记录与回放 |
| 把 `models/DTA/` 放进包内 | 化学依赖判据会扫到 torch 的顶层 import，PyInstaller 还会拖进 2GB 依赖 |
